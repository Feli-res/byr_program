## 应用与调度复验

在本机另开 SSH 隧道：

```powershell
ssh -o UserKnownHostsFile=.local/server-known-hosts -L 18103:127.0.0.1:18103 sunxiang@85.121.122.124
python scripts/verify_final412.py --origin http://localhost:18103 --work .local/final412-02 --readback --out docs/final/restore-readback.json
```

使用备份之前生成的演示账号读取旧帖子、图片、已售商品、暂停任务、私聊和唯一通知。新环境使用独立签名密钥，所以应重新登录；不复制旧 Redis 会话或 WebSocket 票据。

然后在服务器以 Linux Python 环境运行 `--exercise-restore`。需把 `scripts/verify_final412.py`、`scripts/test_support/`、`docs/design/openapi.json` 和演示 fixtures 放到同一私有工具目录的对应相对位置，fixtures 位于 `.local`。使用 Python 3.11 以上，并安装仓库中 `docs/accounts/requirements-tests.txt` 和 `docs/chat/requirements-tests.txt` 指定的依赖。示例（工具树根目录）：

```bash
sudo /实际虚拟环境/bin/python scripts/verify_final412.py \
  --origin http://localhost:18103 --work .local/final412-02 \
  --readback --exercise-restore --out docs/final/restore-scheduler.json
```

此模式只允许 Linux 的 `http://localhost:18103`：恢复已备份任务 → 发布新匹配商品 → **只重启 `youzhihui-restore412-api-1`** → 等待一次提醒 → 再经过一个真实检查周期 → 验证旧消息和新旧通知各一次 → 暂停演示任务、下架探针商品。严禁将此模式改为生产目标。

将数据恢复、应用读取和调度结果下载到 `docs/final/`，再停止恢复容器并保留数据：

```bash
sudo python3 /home/sunxiang/youzhihui/final412-tools/scripts/restore412.py --stop
```

最后下载完整私密备份：

```powershell
python scripts/server412.py download --snapshot 实际UTC目录名
```

备份保存到 `.local/final412-server/offsite-backup.tar.gz`，含真实密码，不放入课程源码包。下载工具会直接读取压缩包，拒绝异常成员并对其中 `SHA256SUMS` 逐项计算 SHA256，成功后生成私有 `offsite-verification.json`；只有该步骤实际通过后才记录异地副本通过。
