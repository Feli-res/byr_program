## 本轮新增的工具

`verify_final412.py` 通过正式 HTTPS 和 WSS 执行真实业务流程，创建带“课程验收412”标签的专用资料，不在试用库执行 SQL、故障注入或删库。商品提醒等待真实五分钟周期，不通过修改服务器时间或任务时间加速。账号密码和对象编号保存到 `.local/final412-02/fixtures.json`，公开结果只包含检查及编号。

`backup_inventory.py` 在网站停止写入期间，记录全部表行数以及上传文件的大小和 SHA256。新版 `backup.sh` 将它与数据库、文件、配置和版本一同校验。必须把这两个文件成对安装到服务器 `shared/`。

`restore412.py` 校验备份后导入**全新** `youzhihui-restore412` 独立卷和数据库，核对全部表行数和全部上传文件 SHA256。HTTP 入口只绑定服务器 `127.0.0.1:18103`；恢复栈不使用生产 Redis、数据库、上传卷或外部文字 AI 密钥。已有恢复环境时拒绝覆盖，失败时停止恢复容器并保留证据。

`server412.py` 使用既有主机指纹校验 SSH，支持只读检查、新版本部署、备份、恢复和下载。服务器密码从 `YOUSHIZHUI_SSH_PASSWORD` 或 `.local/ssh-password.txt` 读取，应用演示密码不能代替 SSH 密码。

`package_final412.py` 打包当前工作区的源码、迁移、说明和真实结果，包含尚未提交的 4.11 修复。排除 `.local`、真实环境文件、依赖、构建缓存及参考仓库副本，生成逐文件清单和包 SHA256；参考源码位置及许可结论仍见原项目说明。

本轮备份安全检查 **5 组通过**，覆盖文件哈希、危险 tar 路径与链接、快照损坏、inventory 缺失及下载副本损坏；Python 编译和恢复 Compose 静态校验通过。随后已经实际执行服务器完整恢复，数据层、HTTP 读取和调度分别保存原始结果。

早期公网脚本的变量覆盖及管理请求遗漏 `target_version` 已修复，原始记录 [initial-flow-run.json](initial-flow-run.json) 保留。正式版本部署时，本机控制台编码异常中断构建控制，确认旧站正常后从已上传版本继续并成功构建；第一次新版流程与计划备份短暂停站重叠，轮询出现一次 502，见 [中断记录](production-maintenance-interrupted.json)。维护完成后复用同一批账号与对象续跑，10 项通过；注册证据与最终流程连续保留，没有把维护停站计成正常无故障运行。
