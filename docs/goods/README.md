# 4.6.2 · 商品和普通搜索

更新日期：2026 年 10 月 28 日。完成真实商品发布、编辑、图片绑定、状态管理，以及公开帖子和商品的关键词搜索。实际结果见 [验收记录](verification.json) 和 [完成记录](completion.json)。

## 一、怎样使用

按 [工程说明](../engineering/README.md) 启动本机项目，原有三个账号继续使用，无需重新初始化管理员。

| 页面 | 能做什么 |
| --- | --- |
| `/goods` | 浏览商品，按关键词、类别、校区、最高价格和商品状态筛选 |
| `/goods/new` | 登录后发布商品，上传并调整图片顺序，填写价格地点等信息 |
| `/goods/{id}` | 查看公开商品详情、图片、出售状态及卖家信息 |
| `/goods/{id}/edit` | 卖家编辑自己的商品，已售或被限制时不能修改 |
| `/me/goods`、`/me/goods/{id}` | 查看本人全部未删除商品，包括已售、主动下架或受管理限制的商品 |
| `/search` | 搜索当前公开帖子与在售商品，按类型及商品条件筛选 |
| `/admin/goods`、`/admin/goods/{id}` | 管理员下架限制或解除限制，填写原因；版主和普通用户无权使用 |

列表筛选、分页条件保存在网址中；从商品或帖子搜索结果进入详情，再点“返回列表”，可回到原条件和页码。私聊入口已在 4.6.3 接入，见 [聊天说明](../chat/README.md)，可从商品详情联系卖家。

## 二、商品与金额规则

- 标题 2～100 字，描述 1～5,000 字；类别、校区、成色使用现有字典，选择“其他”校区须填写地点。
- 价格为 0～99,999.99 元，支持免费。网页严格转换为整数分，后端只接受整数分，不自动四舍五入、不接受超过两位小数或指数写法。
- 品牌、型号、用途、容量和手写笔支持情况可以不填。不知道的信息保留为空，不推测为商品事实；明确的“不支持”保存为 `false`。
- 商品必须绑定 1～6 张本人上传、用途为 `goods_image` 的有效图片，每张不超过 5 MiB。可调整顺序、替换和移除，不能借用别人或已绑定其他内容的文件。
- 内容保存与图片绑定、变更记录一起提交。失败时不留下公开半成品，暂存文件可重试；替换和删除后的旧图片地址立即失效，实际清理后才返还配额。
- 只有卖家可改商品字段。管理员通过管理下架处理内容，不能代卖家改价格。保存时检查版本，过时的编辑被拒绝。

| 当前状态 | 卖家可以改为 |
| --- | --- |
| 在售 | 已预留、已售、已下架 |
| 已预留 | 在售、已售、已下架 |
| 主动下架 | 在售 |
| 已售 | 不能再改状态或内容；可以删除 |

管理员限制的商品不公开，也不能由卖家编辑或重新上架。解除限制不自动恢复在售。已经售出的商品被管理员限制时保留“已售”，解除后仍是已售，防止绕过终态。

普通列表默认在售，主动选择其他状态时可看公开的预留、已售和主动下架商品。受管理限制的详情和图片仅卖家与管理员经身份检查后可读取；删除后普通详情和文件地址均不可读取。

## 三、关键词搜索规则

搜索直接检查当前 MySQL 源记录，公开范围只包括帖子和商品；私聊、个人通知、提醒条件等不进入搜索。

- 帖子匹配标题和正文；商品匹配标题、描述、品牌、型号、用途及交易地点。
- 使用输入的完整关键词进行包含匹配；`%`、`_`、`!` 按普通字符处理，不允许它们变成查询通配符。
- 标题匹配排在其他字段匹配前，同分再按更新时间、类型和编号稳定排序。理由只说明实际命中的字段，不展示虚构 AI 匹配百分比。
- 可选择全部、帖子或商品。指定商品类别、校区或最高价格后，只返回满足这些条件的在售商品；最高价格包含边界，填 0 可筛选免费商品。
- 帖子隐藏/删除、商品预留/已售/下架/删除或被限制后，新的搜索结果立即排除，不等待后续索引更新。
- 当前页面只提供关键词搜索；若 API 收到 `mode=semantic`，会返回关键词结果并明确标记 `degraded=true`、`mode_used=keyword`。真实 AI 搜索在 4.7 接入。

商品和帖子共用同一个变更计数器，与后续搜索更新记录一起提交，为 4.7、4.8 留下数据依据。现在的关键词搜索可以独立工作，不依赖尚未实现的向量服务。

## 五、怎样重复验收

先停止开发程序，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Verify-Goods.ps1
```

脚本执行格式与代码检查、Rust 单元测试、金额转换检查和前端构建，再运行 [实际验收](verification.json)。需先启动 Docker Desktop；检查会真实停止、重启开发专用数据库，不要与其他验收同时运行。

使用独立临时数据库、随机测试账号和合成图片，结束后撤销临时库授权并删除临时库；不修改开发库中的三个指定账号。截图和日志在被忽略的 `.local/logs/goods/`。

检查包括价格边界、非法输入、图片归属与数量、并发编辑、同图并发绑定、状态变化、管理员限制、搜索即时隐藏、分页返回、窄屏、数据库故障和重启读取。Windows 使用 Edge，CI 使用安装后的 Chromium。

Linux / WSL 按工程说明准备后，安装 [现有测试依赖](../accounts/requirements-tests.txt)，构建前后端，运行 `node --test apps/web/tests/unit/money.test.mjs` 和 `python3 scripts/verify_goods.py`。
