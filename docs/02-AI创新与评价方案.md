## 2 AI 能力总体定位

项目只有可复用的社区后端架构，没有成熟用户画像、交易历史和真实成交价格。因此，核心 AI 功能采用低历史数据依赖方案：直接处理商品图片、商品描述、买家明确表达的需求和当前私信内容。

AI 不直接发布商品、不替用户确认交易、不自动封禁用户。所有会影响业务事实的 AI 结果必须经过用户或管理员确认。模型不可用时，普通商品、私信和交易流程仍应运行。

三项核心创新为：

1. 多模态商品发布助手。
2. AI 求购守望与持续供需匹配。
3. 交易协商结构化与风险检查。

## 3 多模态商品发布助手

### 3.1 用户痛点

卖家发布商品时需要填写大量字段，容易遗漏型号、附件、瑕疵和购买时间。低质量图片也会影响买家理解和信任。

### 3.2 输入与输出

输入包括商品图片和卖家主动填写的少量文字。AI 输出可直接填入表单的结构化草稿：

```json
{
  "category": "数码产品/显示器",
  "title": "戴尔24英寸显示器",
  "brand": "Dell",
  "condition": "待用户确认",
  "detectedAttributes": ["约24英寸", "疑似包含HDMI接口"],
  "missingInformation": ["具体型号", "购买时间", "是否包含电源线"],
  "photoWarnings": ["未展示屏幕点亮状态"],
  "descriptionDraft": "请用户确认后生成"
}
```

### 3.3 创新性

- 同时处理图片和文本。
- 输出可进入业务表单的结构化数据，而不是一段孤立回答。
- 区分可确认信息、模型推测和待补充信息。
- 将图片质量检查与发布流程结合。
- 由卖家确认后发布，控制模型幻觉风险。

### 3.4 分阶段范围

- P0：类别、标题、属性、缺失字段和描述草稿。
- P1：图片模糊、过暗、角度不足和缺少瑕疵图等提示。
- P2：以图搜相似商品和更细致的品类属性模板。

## 4 AI 求购守望与持续供需匹配

### 4.1 功能定义

买家可以提前保存想购买物品的自然语言需求。首次检索没有找到合适商品时，需求转化为持续有效的求购守望任务。系统监测新发布、重新上架或信息变化的商品，发现符合条件的物品后主动通知买家。

例如：

> 想买一辆300元以内的自行车，能正常骑，最好在东校区自提，毕业季之前都有效。

AI 将其解析为：

```json
{
  "category": "自行车",
  "maxPrice": 300,
  "requiredConditions": ["可正常骑行"],
  "preferredCampus": "东校区",
  "deliveryMethod": "自提",
  "hardConstraints": ["category", "maxPrice"],
  "softPreferences": ["preferredCampus", "deliveryMethod"],
  "expiresAt": "毕业季前"
}
```

### 4.2 需求确认

AI 区分硬条件、软偏好和待确认信息。类别和最高价格等硬条件不满足时排除商品；校区和自提方式等软偏好用于调整排序；不确定内容必须由买家确认。任务支持有效、暂停、已匹配、已完成、已过期和已取消等状态。

### 4.3 持续匹配

系统采用“商品变化触发为主、定时刷新为辅”的机制：

1. 商品发布、上架或修改后更新语义表示。
2. 使用类别、价格和状态等硬条件筛选候选求购任务。
3. 计算商品描述与需求的语义相似度。
4. 结合价格、校区、成色、交付方式和新鲜度排序。
5. 超过阈值后保存匹配结果并发送站内通知。
6. 定时任务处理失败任务、价格变化和长期未匹配需求。

课程项目的 P0 可以使用数据库任务或简单调度器，不强制引入消息队列。

### 4.4 可解释通知

```text
匹配度 89%

符合条件：
- 商品类别为自行车
- 售价260元，未超过300元
- 描述注明可以正常骑行
- 支持东校区自提

尚未确认：
- 卖家没有说明轮胎近期是否更换
```

买家从通知进入商品详情后可以联系卖家。系统创建或复用商品、买家和卖家对应的私信会话，形成“需求保存—持续匹配—主动通知—买卖私信—交易确认”的闭环。

### 4.5 去重与防打扰

- 每个任务设置最低匹配阈值。
- 同一任务对同一商品只通知一次。
- 商品无实质变化时不重复通知。
- 支持立即通知和每日汇总。
- 设置每日通知上限和冷却时间。
- 提供暂停需求和已经买到的快捷操作。

### 4.6 用户反馈闭环

买家可以选择“符合需求”“价格不合适”“地点不合适”“类型不对”或“不感兴趣”。P0 根据反馈修改条件或排除商品；后续版本可调整软偏好和排序权重。该方案不依赖重新训练模型也能形成反馈闭环。

### 4.7 创新性

- 将长期购买意图转换为可编辑的约束条件和语义表示。
- 不依赖成熟用户画像和历史点击数据，适合冷启动阶段。
- 将一次被动搜索扩展为持续工作的需求代理。
- 结合硬条件和语义相似度，减少单纯向量匹配的误报。
- 新商品和已有求购需求双向匹配，而不是只推荐热门商品。
- 输出匹配原因、未确认项和反馈入口。

### 4.8 分阶段范围

- P0：保存需求、结构化解析、用户确认、手动刷新、商品触发匹配、站内通知和去重。
- P1：定时刷新、通知汇总、匹配解释、有效期和用户反馈。
- P2：根据反馈调整软偏好和排序权重。

## 5 交易协商结构化与风险检查

### 5.1 功能定义

系统从商品对应的私信记录中提取商品、最终价格、成色、附件、见面时间、地点、验货方式和待确认事项，生成双方共同确认的交易卡。

```json
{
  "item": "戴尔24英寸显示器",
  "finalPrice": 180,
  "condition": "屏幕正常，外壳有划痕",
  "includedItems": ["电源线", "HDMI线"],
  "meetingTime": "9月25日18:00",
  "meetingPlace": "东校区一食堂门口",
  "inspectionAgreement": "现场通电检查",
  "unresolvedIssues": ["是否支持退换"],
  "riskWarnings": ["对话中出现提前转账要求"]
}
```

### 5.2 创新性

- 将非结构化协商转换为可确认的交易数据。
- AI 输出进入实际交易流程，而不是停留在聊天回答。
- 识别商品描述、报价和最终协商之间的冲突。
- 引用相关私信作为依据。
- 保留双方确认，避免 AI 代替用户决策。

### 5.3 分阶段范围

- P0：提取关键字段、列出缺失项、双方确认。
- P1：条件冲突、提前转账和站外联系等风险提示。
- P2：更丰富的品类验货清单和风险规则。

## 6 可选与暂缓功能

### 6.1 AI 参考价格区间

可以根据项目内同类商品、成色和附件生成参考区间，但不能表述为准确价格预测。当前缺少真实历史成交数据，因此输出必须说明数据来源和限制。

### 6.2 暂缓功能

| 功能 | 原因 |
| --- | --- |
| 个性化推荐 | 缺少长期用户行为和交互数据 |
| 精确自动估价 | 缺少真实成交价格和成色标注 |
| 欺诈用户预测 | 缺少欺诈样本和交易网络 |
| AI 自动处罚 | 误判风险高，不适合直接执行不可逆操作 |

## 7 测试数据集

建立经过人工检查的课程模拟数据集：

- 不少于100条模拟商品，覆盖8至10个校园常见类别。
- 不少于30条自然语言求购需求。
- 不少于20组商品图片及人工标注字段。
- 不少于20组买卖协商记录。
- 不少于10组存在条件冲突或交易风险的协商记录。
- 正常内容和违规内容各不少于20条。

AI 可以辅助生成文本初稿，但组员必须逐条检查并标注标准答案。报告中应如实称为课程模拟数据集，不能描述为真实校园用户数据。

## 8 评价指标

| 指标 | 评价内容 | 初步目标 |
| --- | --- | --- |
| 商品字段准确率 | 类别、品牌和属性是否与人工标注一致 | 核心字段不低于85% |
| 缺失信息识别率 | 是否发现型号、附件和瑕疵等缺失项 | 以人工标注统计 |
| 条件提取准确率 | 价格、类别和校区等字段是否正确 | 不低于90% |
| 商品匹配 Recall@5 | 相关商品是否进入前5个结果 | 不低于80% |
| 通知准确率 | 通知商品中真正符合需求的比例 | 不低于80% |
| 重复通知率 | 同一需求重复通知同一商品的比例 | 接近0 |
| 匹配延迟 | 商品发布到通知生成的时间 | 数秒至一分钟 |
| 确认卡字段准确率 | 价格、地点和附件等字段是否正确 | 不低于90% |
| 风险提示质量 | 风险识别和误报情况 | 同时报告准确率与误报率 |
| 任务效率 | 使用 AI 前后完成任务的耗时差异 | 使用相同任务对照 |

以上数值是项目目标，需要在实现后使用固定测试集验证，不能提前写成项目结果。

## 9 对照实验

为了证明 AI 功能的价值，至少进行以下对照：

1. 手工填写商品与 AI 草稿后修改的时间和字段完整度对比。
2. 关键词搜索与“硬条件加语义匹配”的 Recall@5 对比。
3. 单次搜索与求购守望对新商品发现耗时的对比。
4. 人工阅读私信与 AI 交易确认卡的字段完整度和耗时对比。

测试报告应说明样本数量、人工标注规则、模型和提示词版本、失败案例及局限性。

## 10 AI 安全与降级

- 所有结构化输出经过字段和类型校验。
- AI 不确定的属性必须标记为待确认。
- 用户输入需要长度限制和提示词注入防护。
- 模型调用设置超时、有限重试、限流和缓存。
- 模型不可用时允许用户手工填写、普通筛选和手工确认交易。
- AI 审核只提供建议，管理员作出最终处理。
- 日志不得保存密钥和不必要的私信全文。

## 11 参考研究

1. Xiao Ma 等人的点对点二手平台研究分析了图片质量与商品销售、买家感知信任之间的关系：[Understanding Image Quality and Trust in Peer-to-Peer Marketplaces](https://arxiv.org/abs/1811.10648)。
2. Andrea Papenmeier 等人整理了包含价格、属性和用途的自然语言商品查询数据：[Dataset of Natural Language Queries for E-Commerce](https://arxiv.org/abs/2302.06355)。
3. Lucas Bernardi 等人讨论了电商推荐系统持续出现的冷启动问题：[The Continuous Cold Start Problem in E-Commerce Recommender Systems](https://arxiv.org/abs/1508.01177)。
4. Nayan Kumar Singh 的研究讨论了从商品图片生成属性和文本描述时的事实一致性问题：[A Multimodal, Multitask System for Generating E-Commerce Text Listings from Images](https://arxiv.org/abs/2510.21835)。
