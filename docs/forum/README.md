# 4.6.1 · 论坛和通用上传

使用现有账户和数据库，实现真实的发帖互动、帖子管理及按用途区分的文件上传。实际结果见 [运行验收记录](verification.json)，阶段总结见 [完成记录](completion.json)。

## 一、怎样打开和使用

在项目根目录按 [工程说明](../engineering/README.md) 准备并启动。原有账号继续使用，无需重新创建管理员；普通用户与管理员的密码不保存在本文件中。

| 页面 | 用途 |
| --- | --- |
| `/`、`/posts` | 公开帖子，按板块筛选，按最新或互动数排序，置顶优先 |
| `/posts/new` | 登录后发帖，选择板块，上传图片和 PDF，预览 Markdown |
| `/posts/{id}` | 查看帖子、附件和评论，点赞、收藏、回复或删除自己的回复 |
| `/posts/{id}/edit` | 编辑或删除自己的帖子；被隐藏时只允许查看或删除 |
| `/me/posts`、`/me/favorites` | 我的帖子与收藏，分页读取真实记录 |
| `/admin/posts`、`/admin/posts/{id}` | 管理员和授权版主管理帖子，置顶/取消、隐藏/恢复及处理评论 |

实际页面在 `apps/web/`，旧的 `docs/page-drafts/` 仍是模拟草图。商品、搜索、私聊和通知页面分别在后续板块接入。

## 二、论坛的使用规则

- 游客可读公开内容，登录后才可发帖、评论、点赞和收藏。每条内容的作者由当前登录确定。
- 至少有“学习交流”“校园生活”两个初始板块。停用板块不能再新发帖，已有公开内容仍可读取。
- 作者只能编辑自己的公开帖子；保存时检查版本，其他窗口已修改则提示重新读取。移动置顶帖子到其他板块会取消原置顶，避免跨板块保留管理效果。
- 重复点赞、收藏和取消不会产生重复记录；评论只能回复同一帖子中可见的评论。
- 隐藏、删除的评论返回占位，不返回正文与作者资料，保留子回复关系。删除不能通过“恢复”重新公开。
- 管理员不能代作者改正文；版主只能处理授权板块。管理操作必须有原因，并与修改结果一起保存记录。
- 正文使用 Markdown，禁用原始 HTML，不执行脚本或危险链接；外部图片不自动加载。图片和附件使用后端检查过的文件地址。

Markdown 使用 [react-markdown](https://github.com/remarkjs/react-markdown) 和 remark-gfm，保留默认链接过滤，不接入原始 HTML 插件。

## 三、通用上传

| purpose | 支持内容 | 单个文件上限 | 绑定数量 |
| --- | --- | --- | --- |
| `avatar` | JPEG、PNG、WebP | 2 MiB | 1 张头像 |
| `post_image` | JPEG、PNG、WebP | 5 MiB | 每帖最多 9 张 |
| `post_pdf` | 可解析的 PDF | 10 MiB | 每帖最多 2 个 |
| `goods_image` | JPEG、PNG、WebP | 5 MiB | 上传已支持，商品绑定与 1～6 张限制在 4.6.2 接入 |

所有用途共用每人 200 MiB 配额。图片检查实际解码、声明类型和扩展名，最长边 4096 像素、解码预算 64 MiB。PDF 通过 lopdf 解析结构，检查页树，拒绝加密及已检查的脚本、活动动作、嵌入文件等内容；解析时每个解压流限制 64 MiB。PDF 以附件下载，设置 `nosniff` 和沙箱响应策略。

前端使用 `lib/upload.js` 统一上传与进度处理，个人头像也使用该方法；`components/files.js` 提供可复用的选择、预览、排序和移除界面。前端请求体转发上限为 11 MiB，以容纳 10 MiB PDF 和上传表单；后端仍执行上述单文件与请求大小限制。

文件上传后仅上传者可读，暂存 24 小时。帖子保存与文件绑定一起提交，失败不会留下公开的半成品。更换、移除或删除后的旧文件立即不可通过原地址读取；真正从磁盘清理后才返还配额。

附件继承帖子权限：公开帖子附件公开可读；隐藏帖子仅作者、该板块授权版主及管理员在重新核验身份后可读；删除帖子不再通过普通文件地址读取。存储目录不会直接对外开放。

## 五、怎样重复验收

先停止本机开发程序，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Verify-Forum.ps1
```

脚本检查格式、编译、单元测试和前端构建，再创建独立临时数据库，执行接口与三个真实浏览器测试；结束后删除本次临时库，保留开发库和已有账号。验收会真实停止、恢复开发专用 MySQL / Redis，不要与其他验收同时运行。

测试包含恰好 10 MiB 的 PDF 经浏览器上传、Unicode 正文边界、并发编辑、重复点赞收藏、跨帖回复、跨板块管理、附件替换/隐藏/删除、配额清理和数据库故障。临时账号、图片、PDF、截图和日志位于被忽略的 `.local/`，不当作真实业务数据提交。

Linux / WSL 先按工程说明准备工具和浏览器，安装 [已有测试依赖](../accounts/requirements-tests.txt)，完成后端与前端构建后运行 `python3 scripts/verify_forum.py`。
