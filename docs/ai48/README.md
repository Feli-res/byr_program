# 4.8 AI 搜索、商品匹配与帖子举报

## 范围

本阶段提供本平台公开帖子和在售商品的关键词或语义搜索；登录用户可输入商品需求，检查并修改 AI 提取的条件，再查询符合硬条件的结果。用户可举报公开帖子，管理员或授权版主人工裁定；文字 AI 建议仅供参考。

4.9 的商品订阅、定时监控和主动提醒尚未实现。论坛侧相似帖子提示为选做功能，本阶段未实现。语义检索使用的相似度阈值是 0.35，排序分数不是匹配概率；具体效果须在 4.11 用标注数据评测。

## 使用

1. 打开“搜索”，填写内容，选择“关键词”或“按意思搜索”。可筛选商品类别、品牌、校区、最高价格、成色和手写笔支持。商品专用条件只匹配商品。
2. 登录后打开“商品”，在“AI 帮你找商品”输入需求并点击“理解需求”。检查并修改类别、品牌、预算、校区和商品属性后确认搜索。AI 不可用时可以手动填写条件，也可以使用普通筛选。
3. 登录后打开公开帖子，点击“举报帖子”，选择原因和说明；在论坛侧栏“我的举报”查看结果。
4. 管理员或授权版主在“举报处理”查看职责范围内的举报、当时快照、当前帖子和 AI 建议，再填写说明并人工裁定。AI 不分析附件，不自动隐藏或封禁；内容变更后旧建议标记过期。

价格、校区、类别、品牌、最低成色和手写笔等已确认硬条件由后端过滤；属性未明确记录时不会算作符合该属性的硬条件。已预留、已售、下架、删除或受管理限制的商品不进入有效匹配。语义索引异步更新，新内容可能稍后出现；返回时重新检查当前可见状态。

## 运行与保护

- 文本理解及举报分析使用 DeepSeek 的 `deepseek-flash`，仅通过后端 HTTPS 调用。密钥只应放在服务器私有环境配置中，不写进网页、源码、日志或示例文件。
- 中文向量模型为 `BAAI/bge-small-zh-v1.5`，通过内部 CPU 向量服务运行，不开放公网端口；MySQL 保存向量，查询时校验源版本与当前可见性。
- 服务默认不开启文本 AI；生产环境设置 `AI_ENABLED=true` 并在私有配置中提供 `DEEPSEEK_API_KEY`。向量服务地址通过后端配置，不由浏览器指定。
- 商品解析每账号每分钟最多 5 次，文本调用还有总并发与 24 小时调用预算限制。AI 不可用时，普通搜索、手动条件和人工举报处理仍可使用。
- AI 举报任务先持久化，再异步执行；请求已发出但结果未知时不自动重复付费调用。疑似含敏感数据、已删除或版本变更的内容转人工处理。

## 验证记录

- 在独立数据库验证从第 5 个迁移版本升级到第 7 个版本。
- 使用真实本机中文向量模型，验证语义搜索、价格/校区/品牌/成色/手写笔筛选，以及属性未知不能满足硬条件。
- 验证举报去重、普通用户和授权版主权限、管理员处理、隐藏后语义搜索不可见、结果通知和 AI 关闭时的降级。
- 浏览器测试覆盖商品需求条件确认、模拟 AI 失败后的手动填写、举报及手机布局；文本模型结果在浏览器测试中使用模拟响应。 本机和线上模拟 13 秒模型响应，均确认网页不会提前中断。
- 账户、论坛、商品、聊天和 4.6 全流程回归通过；后端静态检查和 20 项库测试通过。

上述为独立环境检查，不代表 4.11 的 500 件商品对比评测、多人负载测试或最终验收已经完成。服务器已部署：使用测试账号验证真实 DeepSeek 商品需求解析、举报辅助建议、人工处理与通知，以及实际语义搜索；验收用帖子已清理，处理记录与通知按设计保留。检查服务器私有配置权限为 0600，发布源码和最近前后端日志未发现密钥，前端 HTML 与脚本未发现密钥。
