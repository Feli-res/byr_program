# 4.10 实施计划：管理页面与功能联动

日期：2026 年 10 月 31 日。依据：[计划书 4.10](../../邮智汇_程设项目计划书.md)、[T01 AC16/AC17](../../demand/T01_首版需求基线与验收清单.md)、[设计包](../design/README.md)。

本文只排任务和顺序，不写人员分工。目标是让 4.10 的每一条都能拿出可复现的结果，而不是“页面已经打开过”。

## 一、先把“完成”定死

4.10 完成时，必须同时满足下面五条：

1. 帖子、评论、商品、私信四类举报都能提交、去重、查看、裁定；私信举报只截取必要文字，不提供整段会话。
2. 公告有草稿、发布、撤回三种状态；草稿和已撤回内容不能从任何公开入口读到。
3. 用户、角色、板块、帖子（含评论）、商品、举报、公告、提醒任务都有实际可用的管理入口；版主只看到授权板块。
4. 每个管理动作都在别的页面真实生效，并留下“谁、何时、因为什么、对哪个对象、结果如何”的记录。
5. 有一条独立的验收脚本和一份浏览器检查，覆盖上述内容，并完成原有账户、论坛、商品、聊天、AI、提醒回归。

| 能力 | 现状 | 4.10 还缺什么 |

| 审计查看 | 各管理动作已写 `audit_logs` | 无读取接口；如时间允许补只读页 |

## 三、工作包与顺序

### A. 后端（先做，约 2～3 人日）

**A1 举报统一入口**

- 新增 `POST /api/v1/reports`，请求 `{target_type, target_id, reason}`；保留 `POST /api/v1/post-reports` 作为兼容别名，前端改完后不再新增调用。
- 按类型校验目标当时可见：帖子公开未删；评论所属帖子公开、评论未删；商品未删且未被治理；私信只允许**接收者**举报，发送者举报自己的消息返回 403。
- 在同一事务里锁定举报人、检查同一用户对同一目标的 `pending` 举报，重复时返回已有编号（`already_exists`）。
- 由后端生成快照，客户端不能提交快照：
  - 评论：帖子编号/标题/板块、评论正文、父评论摘要、作者编号、截取时间；
  - 商品：标题、描述、价格分、校区、成色、状态、治理状态、图片引用、截取时间；
  - 私信：被举报消息 + 同一会话中此前最多 4 条，合计不超过 5 条，只存文字、序号、发送方角色、时间；**不返回会话编号和更早历史**。
- 保存举报、管理员/版主持久通知、AI 任务（仅帖子）后提交；提交成功才向用户返回编号。
- 新举报通知范围：帖子/评论 → 全部管理员 + 该板块版主；商品/私信 → 仅管理员。

**A2 列表、详情、裁定通用化**

- `GET /api/v1/admin/reports` 支持 `target_type`、`state`、`board_id`、分页；版主只返回授权板块的帖子/评论举报；商品和私信举报对版主返回 403。
- `GET /api/v1/reports/{id}`：举报人看自己的结果；管理员/版主按范围看快照、当前内容、AI（仅帖子）。
- `PATCH /api/v1/reports/{id}`：检查举报版本、目标版本、处理者当前权限和 `pending` 状态；版本冲突返回 409，前端刷新后再决定。
- 动作矩阵：

| 类型 | 动作 | 同一事务内的联动 | 通知 |
| --- | --- | --- | --- |
| 帖子 | `hide` / `keep` / `dismiss` | `hide`：帖子转 hidden、版本 +1、写 `content_changes(remove)`、索引任务 | 举报人结果；作者“被隐藏”说明 |
| 评论 | `hide` / `keep` / `dismiss` | `hide`：评论转 hidden；帖子详情显示占位，正文不再返回 | 举报人结果；评论作者说明 |
| 商品 | `restrict` / `keep` / `dismiss` | `restrict`：`moderation=restricted` + `state=off_shelf`、版本 +1、索引 remove、不再进入匹配/提醒 | 举报人结果；卖家说明 |
| 私信 | `uphold` / `dismiss` | 不改消息，只记录裁定；不提供会话入口 | 仅举报人结果；不通知被举报人 |

- 所有动作写 `audit_logs`：`report.resolve`，`safe_changes` 记录动作与被治理对象，不写私信正文、不写完整会话。
- 不允许把“成立”做成只改举报状态：隐藏/下架必须与举报裁定同事务完成，不能前端连调两个接口再宣称一起成功。
- AI 任务只对帖子创建；`report_ai_worker` 只处理帖子举报；评论、商品、私信详情返回“此类举报不做 AI 分析”，且绝不把私信送给外部模型。

**A3 公告**

- 公开：`GET /api/v1/announcements`、`GET /api/v1/announcements/{id}`，只返回 `published`，按发布时间倒序；草稿/撤回一律 404。
- 管理：`GET /api/v1/admin/announcements`、`POST`、`GET/{id}`、`PATCH/{id}`。
- 状态机：`draft → published → retracted`；发布设置 `published_at`；撤回后可编辑再发布；已发布内容修改必须先撤回，避免页面缓存与旧公告不一致。
- 标题 2～100、正文 1～20000，沿用 T01；发布/撤回必须填写原因并写审计（`announcement.publish`、`announcement.retract`）。
- 公告不进入全站搜索（现有搜索只索引帖子/商品），未发布公告自然也不会被搜到。

**A4 板块管理**

- `GET /api/v1/admin/boards` 返回含停用板块的完整列表。
- `POST /api/v1/admin/boards`：名称 2～30、描述 0～300，初始启用，重名返回明确冲突。
- `PATCH /api/v1/admin/boards/{id}`：改名/描述/启用状态，版本校验；停用后不能新发帖，已有公开帖子仍可读；不删除历史数据。
- 审计：`board.create`、`board.update`、`board.disable`。

**A5 任务与审计**

- 管理任务列表接口已有，补前端；确认返回字段仍只有 `owner_label/state/interval/last/next/error`，不含条件、原始需求、匹配历史。
- `POST /api/v1/admin/subscriptions/{id}/pause` 已有；页面要求填写原因，成功后任务转 paused、旧租约失效。
- 只读审计接口（有余力再做）：`GET /api/v1/admin/audit-logs`，按对象/动作筛选，只返回白名单字段，禁止私聊正文和私人条件。

**A6 清理**

- 前端全部改用 `/api/v1/reports` 后，`post-reports` 保留但标注为兼容入口。
- 更新 `docs/design/HTTP操作目录.md` 和 `build_contracts.py` 生成文件，避免文档与实现脱节。

### B. 前端（与 A 后半并行，约 2～3 人日）

**B1 统一管理入口**

- 新增 `/admin` 概览页和 `AdminMenu`：管理员看到用户、板块、帖子、商品、举报、公告、任务、审计；版主只看到帖子、举报。
- 论坛侧栏与主导航加入口；无权限时页面显示“没有访问权限”，不只把按钮藏起来。
- 管理页面统一“原因必填、提交中禁用、成功/冲突/失败三种提示”。

**B2 举报入口**

- 评论：每条他人评论旁加“举报”，复用原因类别与补充说明。
- 商品：详情页加“举报商品”，卖家本人不显示。
- 私信：只对接收到的消息显示“举报这条消息”；提交后提示已受理，不提供“查看完整会话”。
- 统一组件参数化 `targetType/targetId`，沿用现有 1～1000 字符校验与重复提交提示。

**B3 我的举报**

- `/me/reports` 显示类型、目标摘要、状态、处理说明和时间；私信举报只显示被举报消息摘要。
- 处理完成后可从通知和“我的举报”两处看到结果。

**B4 举报处理页**

- `/admin/reports` 增加类型筛选、状态筛选、板块筛选（版主固定授权板块）、分页。
- 详情按类型展示：帖子显示快照/当前内容/AI 建议；评论显示评论与所属帖子；商品显示治理状态与图片；私信只显示 5 条以内上下文。
- 动作按钮按类型和状态显示；隐藏/下架按钮旁写清影响；冲突时提示“内容已变化，请重新读取”，不覆盖他人处理。

**B5 公告**

- `/admin/announcements`：列表（草稿/已发布/已撤回）、新建、编辑、发布、撤回；发布/撤回填原因。
- 首页在论坛列表上方显示最新已发布公告标题与时间，点击进 `/announcements/{id}` 只读详情（复用 `SafeMarkdown`）。
- 草稿/撤回不出现在首页，直接访问详情返回“内容不可用”。

**B6 板块**

- `/admin/boards`：列表含停用项、新建、编辑、启停；停用前提示“不能再发新帖，历史帖仍可读”。

**B7 提醒任务**

- `/admin/subscriptions`：脱敏列表、状态筛选、最近/下次检查、错误码、暂停按钮（原因必填）。
- 页面明确“不展示用户条件与匹配历史”。

**B8 管理一致性**

- 所有 admin 页面复用同一个 `Protected admin` / `ManagementGuard`；版主访问管理员专属页显示无权，而不是空白。
- 管理操作后刷新列表，并在相关页面（帖子详情、商品详情）看到最新状态。

## 四、功能联动检查清单（4.10 的核心）

| 管理动作 | 其他页面/接口应看到 | 检查方式 |
| --- | --- | --- |
| 隐藏帖子 | 列表、详情 404；关键词/语义搜索不含；通知目标不可用；附件直链受限 | API + 浏览器 |
| 隐藏评论 | 详情显示“已隐藏”，正文与作者不返回，评论数减少 | API |
| 商品下架 | 列表/搜索/语义/AI 匹配不含；提醒不再新增；历史通知显示“已下架”；卖家不能自行上架 | API + 提醒任务 |
| 封禁账号 | 旧会话 401、实时连接 5 秒内关闭、任务暂停；已发布内容仍按治理状态显示 | API + WS |
| 发布/撤回公告 | 首页与详情出现/消失；草稿直链 404 | 浏览器 |
| 停用板块 | 公开板块列表不含；新发帖被拒；历史帖可读 | API |
| 处理举报 | 举报人“我的举报”和通知看到结果；作者/卖家收到治理说明且不含举报人 | API |
| 暂停任务 | 不再产生新提醒；已有提醒保留；管理员看不到条件 | API |
| 最后管理员 | 不能封禁/降级，并发下仍保留一个可用管理员 | API |
| 任一管理动作 | `audit_logs` 有操作者、时间、原因、对象、结果 | SQL + 审计页 |

“管理页说已下架，搜索和提醒里仍然有效”只要出现一次，4.10 就不算完成。

## 五、风险与需要先定的取舍

1. **接口兼容**：建议新增 `/api/v1/reports`，保留 `post-reports` 一个版本周期；不要直接改旧路径语义。
2. **同事务治理**：评论隐藏、商品下架与举报裁定同事务。若拆成两个接口，必须接受“举报已成立但内容仍可见”的中间态，不建议。
3. **公告范围**：默认首页公告条 + 独立详情，不进入搜索；若课程要求公告可搜，再单独补索引，不在 4.10 临时扩大。
4. **私信举报**：只做“举报—人工查看必要上下文—裁定”，不做消息删除、不做 AI 分析、不通知被举报人，避免暴露举报人。
5. **板块删除**：只停用不删除，历史帖子和外键都保留。
6. **时间**：单人顺序做约 5～6 个工作日；三人按“后端 / 前端 / 验收与文档”并行约 3～4 个工作日，前提是 A1 的接口约定先冻结，前端用固定样例并行开发。
