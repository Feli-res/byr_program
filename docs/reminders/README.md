# 4.9 商品订阅与持续提醒

更新日期：2026 年 10 月 31 日。状态：**本机与试用站均已验收**。试用站版本 `trial-20261031-01`，网站 <https://youzhihui.85-121-122-124.sslip.io>。

本阶段在 4.8 的 AI 商品条件基础上，增加“保存需求 → 定期检查 → 站内提醒”的完整链路。用户确认的条件会保存为提醒任务，后台按周期检查新发布或有更新的在售商品；同一任务对同一商品只提醒一次。首轮检查会逐件提醒当前已经符合条件的在售商品，之后主要检查新增和更新内容。

## 使用

1. 登录后在“商品”页的“AI 帮你找商品”输入需求，确认并修改类别、预算、校区、品牌、成色、手写笔等条件，点击“保存为提醒”，填写名称和检查周期。
2. 也可以打开“提醒”（`/me/subscriptions`），点击“新建提醒”，手动填写条件。至少填写一个条件；空项表示不限制。
3. 在任务列表查看状态、检查周期、最近检查时间、下次检查时间、异常提示和已提醒数量；打开任务可查看条件、执行记录和已提醒商品。
4. 任务可以暂停、恢复、编辑和删除。编辑前会先暂停，保存时可以勾选“保存后恢复”；取消编辑不会自动恢复。
5. 找到商品后，站内通知出现“商品匹配提醒”，点“查看相关内容”打开商品；离线用户重新登录后仍可读取。

新建提醒的检查周期最短 5 分钟、最长 1 天；每个账号最多保留 10 个未删除任务，暂停和异常任务也计入。

## 规则

- **条件**：类别、校区、价格区间、品牌、型号、最低成色、手写笔和容量属于硬条件；用途只保存和展示，不作为“不符合”的依据，避免向量服务不可用时漏提醒。
- **范围**：只检查未删除、在售、未受治理限制且卖家账号正常的商品；不提醒任务所有者自己的商品。
- **首轮与增量**：新建或修改条件后做一次全量检查；之后按共享的内容变更编号只处理新增或更新过的商品。首轮会逐件通知当前所有符合条件商品。
- **去重**：`subscription_matches` 以“任务＋商品”唯一键兜底；改条件、商品重新上架都不清空历史去重记录。
- **暂停/删除/封禁**：暂停或删除会立即失效旧租约；后台在提交通知前再次核对账号、任务、租约和商品状态，旧轮次即使算完也不能补发。
- **失败与重启**：失败按 1、5、15 分钟重试，三次额外重试仍失败进入异常；可手动恢复。进程重启后清理过期租约并按失败进入重试；有效任务继续执行。
- **通知**：通知与匹配在同一事务保存，提交后才推送；推送失败不回滚已保存通知。商品之后被隐藏、删除或限制时，通知只显示“内容当前不可访问”，不泄漏旧正文。
- **管理**：管理员可查看脱敏任务列表并暂停异常任务，接口不返回原始需求、条件或匹配历史；完整管理页面在 4.10。

## 运行与保护

- 不新增数据库迁移，使用 `0002` 已建好的 `subscriptions`、`subscription_runs`、`scheduler_slots`、`subscription_matches` 和通知表。
- 调度 worker 每 5 秒扫描到期任务，最多同时执行 2 个；单任务租约 120 秒，单轮预算 60 秒。
- 检查只使用已保存条件，不重复调用 AI 理解需求；文本模型密钥仍只放在后端私有配置。
- 管理、暂停、删除和通知读取都沿用现有登录、CSRF、来源和权限检查。

## 边界

- 4.9 的提醒资格由硬条件决定；用途只保存和展示，当前不按语义相似度排序。语义搜索和商品匹配的 500 件对比评测仍在 4.11。
- 不做短信、邮件、微信等站外推送；不做跨板块持续提醒。
- 4.10 才提供完整管理页面、评论/商品/私信举报和公告联动。
- 本记录包含独立库本机验收和试用站基本流程复验；不代表 4.11 的 500 件商品效果对比、多人负载或 4.12 的完整备份恢复演练已经完成。
