# 4.6.3 · 聊天和通知

更新日期：2026 年 10 月 28 日。已接入真实私聊、历史消息、未读、断线补读及个人通知通道。结果见 [验收记录](verification.json)、[完成记录](completion.json)。

## 一、怎样使用

按 [工程说明](../engineering/README.md) 准备并启动项目，沿用原来的三个账号。已有数据库执行准备命令时会自动补上第五个数据库版本，不需要重新注册或初始化管理员。

| 入口 | 可以做什么 |
| --- | --- |
| 商品详情的“联系卖家” | 登录后进入与该商品卖家的会话，不能联系自己 |
| `/messages` | 查看本人会话、最后一条消息和各会话未读数量 |
| `/messages/{id}` | 发送文字、读取历史、加载更早消息、补读最新消息及推进已读位置 |
| `/notifications` | 查看本人通知，筛选未读，单条或全部标记已读 |

演示时用两个独立浏览器或一个普通窗口加一个无痕窗口，分别登录两个普通账号。一方发布商品，另一方在详情中联系卖家，然后两边发送文字、刷新并重新登录，检查历史仍在。导航中已加入“私聊”和“通知”。

通知列表在没有通知时显示空内容。商品匹配提醒和举报结果分别在 4.9、4.10 接入；本阶段已完成它们共用的保存、读取、已读和推送方法。验收通知只写入独立测试库，不给真实账号插入演示通知。

## 二、聊天规则

- 卖家由后端根据商品查出；同一对用户始终复用一个会话，保留首次联系的来源商品。来源商品隐藏、删除或受限制后，原聊天仍可读，商品上下文改为不可用。
- 仅双方可以读取或发送，管理员身份也不能查看其他人的私聊。对方被封禁或要求重置密码时，不能向其发送新消息。
- 消息为 1～2,000 个 Unicode 字符的纯文字，按文本显示；不支持聊天图片或附件。
- 每条消息先保存，再确认成功。重试沿用原发送标识：正文相同返回原消息，正文不同拒绝，避免重复保存。
- 历史默认最新 20 条，向前翻历史、向后补读使用会话内序号；每次最多 100 条。实时事件和普通请求结果按消息编号合并，不按网络到达顺序排列。
- 未读只计算对方发来、且超过本人已读位置的消息。页面可见并查看最新消息时才推进已读，旧位置不能覆盖新位置。
- 连接不可用时继续通过普通请求发送和补读；未确认成功的消息保留在当前页面供重试，不显示虚假成功。关闭网页不会保存待发草稿，已经保存的消息可重新读取。

## 三、实时连接与通知

网页通过同一地址的 `/api/v1/ws` 连接后端，实际经过 Next.js 转发已验证。连接使用登录 Cookie，先取 30 秒有效、仅用一次的票据，再在首帧认证；票据不出现在网址中，Redis 只保存摘要和会话绑定。来源必须与 `WEB_ORIGIN` 完全一致。

后端每 500 毫秒检查登录状态，也在处理业务和推送前检查。退出只关闭当前登录的连接；改密、重置和封禁影响相关全部旧登录，到期同样关闭。五种情况都已实际测得小于 5 秒，具体时间见验收记录。数据库暂时无法确认身份时关闭连接，前端保留失败状态并重试连接。

网页每 30 秒发送心跳，连续两个周期未收到响应就重连；连接恢复后从数据库补读。当前单个 API 进程最多 128 条连接，每个登录最多 16 条，每条连接排队最多 64 个提示；单帧上限 32 KiB，每条连接每 5 秒最多 60 帧。

消息、通知与待推送引用一起提交。推送额外重试最多 5 次，等待 1、5、15、60、300 秒，最终失败记录安全告警。推送成功只表示提示已进入在线连接队列，持久消息和通知仍以数据库为准；离线用户依靠查询补读。已用真实临时读锁验证重试和最终停止，不会因此删除已保存消息。

通知只返回本人内容。每次列表读取和实际推送都重新检查目标的当前状态；隐藏、删除或无权读取的目标显示安全占位，不继续使用旧标题或摘要。全部已读只处理当前范围，新通知仍保持未读。

当前连接注册表在单个 API 进程内，适合本项目现阶段；以后若启动多个 API 实例，需要补充跨进程分发。云服务器的 WSS、HTTPS 和代理配置在 4.12 实测。

## 五、怎样重复验收

先打开 Docker Desktop、停止正在运行的开发程序，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Verify-Chat.ps1
```

脚本检查格式、代码、单元测试和构建，再运行 14 组聊天检查及 4 个真实浏览器测试。检查会停止、重启开发专用 MySQL/Redis，不要与其他验收或日常开发同时运行。使用独立临时库和随机测试账号，结束后删除临时库，不改动开发账号。截图和日志保存在被忽略的 `.local/logs/chat/`。

Linux / WSL 准备好前后端后，安装 [账户测试依赖](../accounts/requirements-tests.txt) 与 [聊天测试依赖](requirements-tests.txt)，执行 `python3 scripts/verify_chat.py`。Windows 使用 Edge，CI 使用 Chromium；CI 配置已补充，远端尚未执行。

通知验收命令同时要求测试开关和实际连接的专用随机临时库名，正常运行没有公共通知创建接口。匹配和举报功能以后直接调用共用通知方法。
