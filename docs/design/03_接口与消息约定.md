# 前后端怎样传递信息

本文件固定交互规则，完整路径和字段见 [HTTP 操作目录](HTTP操作目录.md) 与 [openapi.json](openapi.json)。以下路径与字段是开发约定；账户、4.6.1 论坛及通用上传已在正式工程接入，原 HTML 草图仍不调用它们。

## 一、共同格式

- 路径前缀 `/api/v1`，普通请求与响应为UTF-8 JSON；上传用 `multipart/form-data`，下载返回经过权限检查的文件字节。
- 编号为字符串，例如 `"42"`；序号也为字符串，允许 `"0"` 表示尚未读取。金额用整数分，例如2200元为 `220000`。
- 时间为UTC，例如 `2026-10-23T08:30:00.000000Z`。前端按上海时区显示，不把显示文案当作传输时间。
- 普通分页 `page` 从1开始，默认20条，`page_size` 为1～100。稳定排序最后用ID打破平局；帖子置顶优先，最新按创建时间/ID倒序，热门按互动数/创建时间/ID倒序；会话按更新时间/ID倒序。
- 消息历史用序号游标，见第四节。普通列表翻页期间有新增内容可能移动位置，实时消息补读不采用页码。
- `version` 是客户端读到的版本。帖子/商品/资料更新提交它；任务提交 `config_version` 作为请求字段 `version`。不匹配返回409，提示重新读取并比较，禁止静默覆盖。
- JSON中不接受未声明字段；长度、枚举、金额、字典、资源归属由后端重新检查，不能只依赖页面按钮。

成功：

```json
{"data":{"id":"42"},"meta":{"request_id":"b184f489-3ceb-4b92-8845-a290c7e93cab"}}
```

失败：

```json
{"error":{"code":"VALIDATION_FAILED","message":"请检查填写内容","fields":[{"path":"price_cents","message":"最高为9999999分"}],"retryable":false},"meta":{"request_id":"b184f489-3ceb-4b92-8845-a290c7e93cab"}}
```

| HTTP | 常用业务码 | 页面处理 |
| --- | --- | --- |
| 400 | `INVALID_JSON`、`INVALID_CURSOR` | 提示请求或游标不合法，不重复提交原错误 |
| 401 | `AUTH_REQUIRED`、`SESSION_EXPIRED` | 清理本地登录视图，跳登录；不保留密码 |
| 403 | `FORBIDDEN`、`ACCOUNT_BANNED`、`PASSWORD_RESET_REQUIRED`、`CSRF_INVALID` | 说明无权限/账号限制；不继续操作 |
| 404 | `NOT_FOUND` | 内容不存在或不可公开查看，隐藏旧内容与附件 |
| 409 | `ACCOUNT_TAKEN`、`VERSION_CONFLICT`、`STATE_CONFLICT`、`IDEMPOTENCY_CONFLICT` | 账号重复就修改；版本冲突重新读取；同消息标识不得换正文 |
| 413/415 | `FILE_TOO_LARGE`、`UNSUPPORTED_FILE_TYPE` | 文件旁显示错误，不加入发布列表 |
| 422 | `VALIDATION_FAILED`、`CONFIRMATION_REQUIRED`、`FILE_QUOTA_EXCEEDED`、`TASK_LIMIT_REACHED` | 保留非密码输入，指明字段或配额限制 |
| 429 | `RATE_LIMITED` | 使用 `Retry-After` 显示等待；不自动重复收费AI请求 |
| 503 | `DEPENDENCY_UNAVAILABLE`、`AI_TIMEOUT`、`AI_INVALID_OUTPUT` | 保留非密码输入；AI改手填，语义搜索可降级；写入失败不显示成功 |

不可见对象优先404，避免泄漏他人内容是否存在；本人明确的治理限制可在本人管理接口显示。错误不包含SQL、磁盘路径、密钥和堆栈。

## 二、登录、会话与请求保护

1. 网页先 `getCsrf`，获取签名防跨站凭据；服务器同时设置host-only `byr_csrf` Cookie。签名绑定当前会话，未登录时绑定匿名随机量。
2. POST/PUT/PATCH/DELETE提交 `X-CSRF-Token`，与Cookie匹配且签名有效；服务器检查来源在完整白名单中，不接受任意或null来源。注册、登录和重置也遵守这一规则。
3. 登录创建32字节以上随机会话令牌，数据库仅存摘要；浏览器接收host-only `byr_session`，HttpOnly、SameSite=Lax，正式HTTPS配置Secure。开发HTTP仅限本机配置，不沿用正式密钥。
4. 有效期从登录起7天，不静默续期。注册不自动登录，注册结果返回公开用户字段，随后进入登录页。
5. 退出撤销当前会话；改密、管理员重置或封禁撤销全部会话。受保护请求每次校验用户状态和会话，WebSocket同样检查。
6. 管理员核实后签发一次性重置凭据，最长30分钟，只允许改密。数据库存摘要，响应明文只展示一次且禁止缓存；成功后消费凭据、撤销会话、清除强制重置标记，要求重新登录。过期须重新签发。
7. 密码、Cookie、CSRF/WS票据和私人输入不写访问日志；记录路由模板、请求编号、结果和耗时即可。

初始化首位管理员使用独立本机命令，由操作者交互式设置非示例密码；仅在尚无管理员时允许创建，写入Argon2id哈希，初始 `password_reset_required=false`，不借用必须由另一名管理员签发的重置流程。没有公开“注册管理员”接口。最后可用管理员的保护见第04份说明。

正式部署时前端和API通过同一HTTPS来源提供；本机开发可用前端 `http://localhost:3000`、API `http://localhost:8080`，均由配置明确允许，浏览器请求使用 `credentials: include`。开发跨来源时只回显白名单Origin、允许凭据和X-CSRF-Token，并开放Retry-After响应头读取，不使用星号来源。文件URL为API路径，前端相对于配置的API来源解析；生产同源后不需要把后端磁盘或其他来源暴露出来。

## 三、发商品的完整交互例子

页面先分别上传图片，得到已经验证的文件ID；随后提交商品。下面是字段格式示例，不是已经创建的数据：

```json
{
  "title":"iPad Air 4，附二代 Pencil",
  "description":"64G，屏幕正常，配件和使用痕迹见图片。",
  "category_id":"1",
  "brand":"Apple",
  "model":"iPad Air 4",
  "purpose":"记笔记",
  "condition_code":"like_new",
  "price_cents":220000,
  "campus_code":"shahe",
  "location_text":"图书馆门口",
  "attributes":{"stylus_support":true,"storage_gb":64},
  "image_file_ids":["11","12"]
}
```

后端确认当前账号正常、字典有效、金额和图片符合规则、文件属于自己且用途正确；一个事务保存商品、绑定及内容变更。成功返回201和完整 `Goods`，网页进入详情。数据库失败返回503，网页保留字段，不显示“发布成功”。

上传文件先验证真实类型/解码并写入私有暂存位置；成功记录的暂存文件计入配额，24小时未绑定进入清理。磁盘写入后数据库失败时不暴露该路径，并安排孤立文件清理。文件读取先验证当前权限再返回，包括304缓存命中；默认 `Cache-Control: private, no-cache`。不得把上传目录作为公开静态目录。

## 四、聊天和通知的实时事件

### 连接过程

先通过带CSRF保护的 `createWsTicket` 获取单次票据（30秒，绑定会话，Redis只保存摘要与绑定）。连接正式站点的 `/api/v1/ws`，使用会话Cookie，服务器先核对完整Origin白名单；5秒内首帧发 `authenticate`，消费票据后才允许订阅或收消息。票据不放URL。生产使用WSS。

Redis票据不可用则返回503，界面可继续HTTP发送/补读，不把WebSocket可用当作数据已保存。

| 方向 | type | data字段 | 行为 |
| --- | --- | --- | --- |
| 客户端→服务端 | `authenticate` | `ticket` | 绑定Cookie对应会话、一次消费、检查到期 |
| 服务端→客户端 | `ready` | `user_id`、`session_expires_at` | 认证完成，客户端开始同步本人数据 |
| 客户端→服务端 | `message.send` | `conversation_id`、`client_message_id`、`body` | 与HTTP发送同一个业务命令；再次校验会话成员和账号 |
| 服务端→发送端 | `message.ack` | `Message` | 事务提交后返回；据此把“发送中”改为“已保存” |
| 服务端→成员 | `message.created` | `Message` | 多设备也可收到；按会话序号/消息ID去重 |
| 客户端→服务端 | `message.read` | `conversation_id`、`through_sequence` | 只推进自己的已读位置 |
| 服务端→成员 | `conversation.read` | `conversation_id`、`reader_id`、`through_sequence` | 更新已读展示，不透露其他会话 |
| 服务端→接收者 | `notification.created` | `Notification` | 提交后推送；以持久通知为准 |
| 服务端→客户端 | `unread.updated` | `conversation_id`、`message_unread_count`、`notification_unread_count` | 更新本人的角标；重连通过HTTP重算 |
| 客户端→服务端 | `ping` | 空对象 | 每30秒发送心跳；连续两个周期无响应关闭并重连 |
| 服务端→客户端 | `pong` | `server_time` | 响应心跳 |
| 服务端→客户端 | `session.revoked` | `reason_code` | 退出、过期、改密或封禁后通知并关闭，最迟5秒；期间不接收新业务消息 |
| 服务端→客户端 | `error` | `code`、`message`、`retryable`；request_id在外壳 | 统一错误，不输出内部详情 |

实时帧统一外壳，JSON文本，不接受二进制聊天附件；单帧上限32 KiB，`body`仍按2000码点限制。事件类型未知或字段错误拒绝，不能只在握手时做一次权限判断。

机器可读字段见 [ws-events.json](ws-events.json)。未认证或失效使用关闭码4001，无权限4003，认证等待超时4008，临时过载1013。票据发送后、收到ready前不发送业务帧。

```json
{
  "type":"message.send",
  "request_id":"13a550c3-86fb-4398-9167-15482105e024",
  "data":{"conversation_id":"7","client_message_id":"267efdf5-e641-4cef-b112-2d86b1751e1a","body":"你好，周末可以在沙河看商品吗？"}
}
```

服务端事件另带 `event_id`、`occurred_at`。消息事件ID按消息ID稳定生成，通知按通知ID生成；客户端不拿事件的网络到达顺序代替会话序号。

### 消息保存、重试与补读

- 锁会话行，检查双方身份和发送者成员资格；存在相同“会话＋发送者＋client_message_id”时比较正文摘要，相同返回原消息，不同报409。
- 新消息分配会话内递增序号，与消息及待推送引用同事务提交。HTTP首次201，幂等重放200；WS返回原ack。UI不能用本地气泡出现作为成功依据。
- 首次读取默认最新20条并按sequence正序展示。滚动旧消息用 `before_sequence`；断线补读用 `after_sequence`，两者互斥，limit默认20上限100；有更多就循环读取。
- 重连先建立连接并缓存新事件，再用HTTP补到最新；合并缓存时按消息ID/sequence去重，避免补读与实时交叉造成缺漏。
- 同一会话相同双方只创建一次，商品卖家从数据库决定，不能由客户端伪造发送者。未读只统计对方且序号超过本人已读位置的消息。
- 断线重试沿用原client_message_id，不生成新UUID。页面重启可保存非敏感待发草稿，密码和会话令牌不存网页localStorage。

## 五、通知和降级

通知与聊天分开存储、分开计未读。事务提交后推送，即使推送失败或用户离线，通知仍可在下次查询时读取。通知列表返回时重新判断商品/帖子当前可见性；不可见目标只显示占位，不用旧快照泄漏标题、图片或匹配条件。

关键词检索、手动条件与HTTP消息补读不依赖外部模型。模型超时或乱格式不自动反复收费；语义适配器故障可以返回明确的关键词降级结果。依赖失败的写入返回错误，不能只在页面上假装完成。

登录/解析的限流存储不可用时返回503，不临时放开限流。outbox网络推送额外重试最多5次，等待1、5、15、60、300秒，仍失败标记expired并记录安全告警；本人HTTP历史/通知读取继续可用。此处是网络推送重试，和商品监控的3次额外重试分开。

本设计的会话、来源检查与实时逐次权限检查参考 [OWASP WebSocket 指南](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html)、[CSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)；具体业务参数仍以T01为准。
