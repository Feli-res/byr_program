## 三、怎么读这些数字

- 关键词基线使用完整自然句做 `LIKE`，36 条全部零命中；这只能说明“同义/用途句下关键词失效”，不能证明语义在所有查询上都优于关键词。
- 语义搜索 NDCG@10 0.9057；AI 确认条件组 0.8889，略低于纯语义，原因是条件提取和过滤会缩小候选集；但硬约束违规为 0，且都高于关键词基线。
- 同义子集 R@5：语义 0.0663、AI 0.0728，均高于关键词 0；但绝对值低，因为每题有约 50～100 件相关商品，R@5 的分母很大。P@5 约 0.89～0.91 说明前五条基本相关。
- 字段准确率中 category 95%、其余 100%，达到 90% 目标；硬约束 0 达标。
- 提醒 20/20 正例、20/20 反例、0 重复；P95 100.2 秒低于 420 秒目标。测试用 SQL 把任务置为到期，报告里记录为“到期模拟”，不是自然等待 5 分钟。

## 四、限制

1. **标注流程**：金标是规则生成 + 抽样核对，不是双人独立逐条标注；查询与金标见 `queries-40.json`、`labels-40.json`。负责人已取消双人复核要求，该方法说明保留为评测解释边界。
2. **关键词基线**：完整自然句导致零命中，比较结果偏保守；不能把“语义 0.9”解释成所有真实用户查询都同样好。
3. **模型调用**：首次 40 次调用有 7 次 503、4 次 429；脚本重试后 40 条全部完成。字段准确率以最终成功结果计算，失败重试记录保留在 `intent-raw-411.json`。
4. **环境**：411 是 1.5 CPU 隔离栈，不是生产 HTTPS 入口；生产复验仍归 4.12。
