# 4.11.3 负载测试：修复后复测

日期：2026-11-03。环境：服务器 `youzhihui-411` 隔离栈，4 vCPU / 16 GiB 宿主机；411 slice 1.5 CPU，API 1 CPU / 512 MiB，MySQL 512 MiB / 1 CPU，embedding 1024 MiB / 1 CPU。**结果是在 1.5 CPU 隔离配额下测得，不代表整机 4 核满配。**

镜像：`youzhihui-api:411-fix2`。原始结果：[完整 5 分钟](load-411-after-fix2.json)、[仅 WS 5 分钟](ws-only-after-fix.json)、[空载索引探针](probe-index-after-fix.json)、[索引时间核对](index-after-fix.json)。

## 一、修复内容

### 1. 索引吞吐与优先级

文件：[semantic.rs](../../services/api/src/semantic.rs)。

- 查询和索引分开信号量：查询 4 槽、索引 2 槽，避免搜索请求把索引饿死。
- 索引批大小 25、并发 2、每 2 秒运行一次；不再固定 10 条/5 秒。
- 商品优先于帖子：每轮先取商品待索引行，再补帖子。
- 单条索引失败只影响该条，不再让整批回滚；任务保留到下一轮。
- embedding 客户端复用同一个连接池；查询等待 500 ms、请求 3 秒；索引等待 2 秒、请求 5 秒。
- 保留原有版本校验和可见性过滤。

### 2. WebSocket 会话检查

文件：[realtime.rs](../../services/api/src/chat/realtime.rs)。

- 会话检查超时 1 秒 → 2 秒；检查间隔 500 ms → 1 秒。
- 事件 payload 超时 1 秒 → 2 秒。
- `unread` 计数单独加 1 秒超时，超时不再直接关闭连接。
- `valid()` 超时/失败分支写明确的 warn 日志，便于下次定位 1013。
- 改密/封禁撤销仍在 5 秒约束内。

### 3. 造数脚本

文件：[seed_411.py](../../scripts/seed_411.py)。注册后显式登录；修正 25 个会话选择商品的归属关系。该问题只影响造数，不是产品代码。

### 3.3 索引

- 空载单条商品：数据库 ready **1.36 秒**，语义搜索可见 **1.61 秒**。
- 完整负载下新商品 502：创建 `2026-11-03 07:57:42.679540`，索引 `07:57:44.734906`，**2 秒**。
- 压测结束后 3,800 个索引任务全部 succeeded，0 pending；3,298 帖 + 502 商品 ready。

**口径说明**：`load-411-after-fix2.json` 里的 `index_sync_seconds=367.57` 是压测结束后才开始轮询的测量值，包含 300 秒负载等待，不是索引耗时；实际耗时以 `goods.created_at` 与 `search_documents.indexed_at` 的差为准，见 [index-after-fix.json](index-after-fix.json)。下一轮应把索引轮询改成与负载并行。

### 3.4 语义降级

- 模式计数 1,248 次（含 30 秒预热）：`semantic` 1,202 次，`keyword degraded` 46 次，降级率 **3.7%**。
- 测量窗口内语义样本 1,022 条，P95 2.364 s；成功语义比例约 96.3%，高于 95% 目标。
- 首测诊断轮约 27% 降级，修复后明显下降；剩余 3.7% 仍需在报告中保留，不能写成 0。

## 四、试用站影响

- 保护监控全程未触发：可用内存约 13.2～13.4 GiB，试用站 readiness 约 2～6 ms，无 OOM，五个 strike 均为 0。
- 411 API/MySQL/embedding 在负载时仍受容器/ slice 限制；宿主 load 升高，但试用站正常。
- 试用站 5 个容器 ID 与压测前一致，4 个数据卷名称未变化；411 使用独立库和上传卷。
- 压测结束后 411 六个容器已停止，数据卷保留；试用站健康检查 200。

## 五、判定

- **HTTP 延迟：通过**（七类 P95 和 ≥95% 达标比例均满足；提醒延迟沿用首轮 5/5、P95 108.8 s）。
- **索引同步：通过**（空载 1.61 s，满载 2 s，0 pending）。
- **聊天连接：通过**（0 次 1013，149 条仅 WS、145 条混合负载均无错误）。
- **语义有效性：通过**（约 96.3% 真正走语义，P95 2.364 s；3.7% 降级如实记录）。
- **限制**：411 是 1.5 CPU 隔离栈，不是生产 HTTPS 入口；4.12 仍需在试用站生产栈复验 Nginx/HTTPS/真实数据。

因此 4.11.3 可以记为“**411 隔离栈通过**”，AC19 从“部分通过”更新为“隔离栈通过，生产复验待 4.12”。
