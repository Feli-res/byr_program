# 邮智汇首版需求基线与验收清单

版本：V1.1。日期：2026 年 10 月 26 日。状态：需求统一完成，账户功能已在本机验收；其余功能按计划推进。

本文件是当前开发与验收的需求依据，固定首版范围、权限、状态、资源参数及验收标准，供 T02 详细设计和后续开发使用。项目规划和 AI 方案已按本基线同步；原 Word 按用户要求保持不变，其差异见第十节。新增功能或调整数值时，更新本基线及相关 Markdown 并记录原因。以下数值是首版验收目标，不是已测得的性能或效果。

## 一 首版范围

| 编号 | 必做模块 | 交付边界 |
| --- | --- | --- |
| F01 | 自主账户 | 注册、登录、登出、个人资料、头像、会话撤销、管理员辅助重置密码；普通用户、版主、管理员三种角色 |
| F02 | 论坛交流 | 至少学习、生活两个板块；帖子发布编辑删除、评论回复、点赞收藏、版主置顶及隐藏处理；正文支持安全渲染的 Markdown，不执行原始 HTML |
| F03 | 全站搜索 | 关键词与向量语义搜索均必做；搜索平台内可公开访问的帖子和商品，标明类型，支持适用筛选、分页及结果依据 |
| F04 | 二手商品 | 标题、描述、类别、品牌或型号、用途、成色、价格、校区地点、图片和状态；发布编辑、筛选及联系卖家 |
| F05 | 私聊与通知 | 一对一文字私聊、持久历史、发送确认、未读及重连补读；站内通知单独展示，支持已读 |
| F06 | AI 商品匹配 | 自然语言解析、用户修改并确认条件、硬条件过滤、语义排序和基于商品信息的匹配解释；失败可普通筛选 |
| F07 | 商品监控 | 确认条件后保存任务；周期增量匹配、启停编辑删除、去重提醒、有限重试、执行状态及重启恢复 |
| F08 | 管理治理 | 用户封禁、角色和板块授权、帖子处理、商品下架、举报处理、公告、任务概览及关键操作审计 |
| F09 | 工程交付 | 本地与 Docker Compose 启动、配置示例、迁移、日志、健康检查、功能及权限测试、AI 对比评测、部署和备份恢复说明 |

RAG、AI 发帖助手、伙伴匹配、跨板块帖子监控均不进入首版验收。首版不接校园 CAS，不标记学校认证身份，不采集学校门户密码，不抓取官方论坛数据；不做支付托管、群聊、音视频、聊天文件传输和双语页面。

技术栈固定为 Next.js/React、Rust/Salvo/Tokio 模块化单体、MySQL/SQLx、Redis、本地文件存储。文本解析模型和 Embedding 接口可替换，向量组件在 T02 设计与 4.8 接入试验中选定，语义能力本身不再列为可选。AI 只处理本平台有权使用的内容，不传输密码、私聊或私有附件。

## 二 账号与会话

- 注册账号为 4～24 位 ASCII 字母、数字或下划线，首位为字母；去除首尾空白并统一小写后判断唯一。昵称为 2～20 个字符，简介最多 300 个字符；公开显示昵称，不公开登录标识。
- 密码为 8～64 个 Unicode 字符，不截断、不自动去空白；以 Argon2id 哈希保存，具体计算参数在实现时记录。注册只能获得普通用户角色，管理角色由授权管理员分配；初始管理员通过独立初始化流程创建。
- 会话从登录起绝对有效 7 天，不做静默续期；到期重新登录。登出撤销当前会话，修改或重置密码、封禁账户撤销全部会话。每次受保护操作校验账户和会话状态；撤销后实时连接最迟 5 秒内关闭，期间不接受失效账户的新消息。
- 同一账号或 IP 在 15 分钟内累计 5 次登录失败，后续尝试限制 15 分钟并返回可理解提示，不泄露账户是否存在。具体限流存储设计归 T02。
- 首版提供管理员核实后辅助重置密码，不做短信或邮件自助找回。重置生成一次性临时凭据，最长有效 30 分钟；只允许进入改密流程，修改后才能使用业务。不得记录明文密码；操作记录审计。

文本长度按 Unicode 码点计数；正文和普通业务文本先做空值及长度校验，密码按上述单独规则处理。

## 三 权限与数据可见范围

| 操作或数据 | 游客 | 普通用户 | 版主 | 管理员 |
| --- | --- | --- | --- | --- |
| 公开帖子、商品、公告及普通或语义搜索 | 可读 | 可读 | 可读 | 可读 |
| 发帖评论、点赞收藏、发商品 | 不可 | 管理本人内容 | 同普通用户 | 同普通用户 |
| 编辑他人正文或商品字段 | 不可 | 不可 | 不可 | 不代作者修改；通过隐藏、下架等治理操作处理 |
| 置顶、隐藏帖子及处理评论 | 不可 | 只能删除本人内容 | 仅授权板块 | 全站 |
| 下架他人商品 | 不可 | 不可 | 不可 | 可，记录原因与审计 |
| 会话、消息、已读状态 | 不可 | 仅会话成员 | 同普通用户 | 同普通用户，无默认浏览全站私聊权限 |
| 监控条件、原始需求与个人通知 | 不可 | 仅本人 | 仅本人 | 默认仅本人；任务管理只显示脱敏运行元数据，可暂停异常任务，不改写他人条件 |
| 举报 | 不可提交 | 可举报、查看自己的处理结果 | 处理授权板块内容举报 | 处理全站举报；骚扰举报只查看被举报消息及必要上下文，不开放整段私聊 |
| 封禁、角色、板块配置、公告与审计 | 不可 | 不可 | 不可 | 可；禁止移除最后一个可用管理员 |

封禁账户不能执行任何受保护操作，其有效监控任务自动暂停；解封后由用户主动恢复任务。已发布内容是否隐藏或下架由治理动作另行决定。作者不能修改被管理员隐藏的内容以绕过处理。

全站公开搜索排除私聊、个人任务、私人通知、未发布公告、已隐藏或删除的帖子及无权访问的附件。普通商品检索默认只显示在售商品，用户可主动查看其他公开状态；AI 匹配和监控只接受在售商品。搜索返回前再次检查数据库中的可见性，不能仅依赖可能滞后的向量索引。

附件继承所属内容的访问规则，不能凭直链绕过隐藏、删除和权限变化；头像为公开资源。管理员身份本身不授予私有附件访问权。

## 四 状态和处理规则

**帖子与公告：**帖子发布后可见，作者可编辑或删除，版主按板块授权隐藏或恢复，管理员可全站处理；恢复前检查记录是否已删除。公告为草稿、已发布、已撤回，只有已发布内容公开。首版采用发布后举报治理，不要求每篇内容先审后发；管理员解除治理限制后作者才可重新编辑。

**商品：**状态统一为在售、已预留、已售、已下架。卖家可在“在售↔已预留”间切换，在售或已预留可转为已售或主动下架；主动下架后可重新在售。已售为终态，不恢复在售；管理员下架的商品须先解除治理限制，卖家才能重新发布。已预留、已售、已下架、已删除或被限制的商品均不进入新的 AI 匹配与监控提醒。

**监控：**状态为启用、暂停、异常、已删除；执行中的标记属于单轮执行记录，不另当作用户状态。任务只在用户确认条件后创建或启用；修改条件前暂停，保存成功后由用户确认是否恢复。失败退避重试期间不启动新的周期，首次执行失败后最多额外重试 3 次，等待分别为 1、5、15 分钟；仍失败则转异常，用户可修正后手动恢复。单轮最长 60 秒，领取租约 120 秒，租约过期可回收；同时最多执行 2 个任务。

**去重与恢复：**以任务和商品的唯一关联防止重复提醒，商品反复编辑不重复通知；修改任务条件也保留已有去重记录。新任务和修改条件后的首轮允许匹配当前在售商品，后续按新增或更新增量检查。匹配关联和通知在同一事务中写入，提交后推送，失败不推进增量游标。暂停、删除或封禁后，即使已有执行在途，也不得提交新的匹配通知；重启后恢复启用任务，合并错过的周期，不集中补跑每一轮。

**消息与通知：**消息保存后才确认成功；相同会话、发送者与客户端消息标识的重试只生成一条消息。在线推送失败不撤销已保存的消息或通知，重连以持久记录补读；历史通知展示目标当前状态。业务数据以 MySQL 为准，Redis 调度索引和缓存可重建。

## 五 资源参数

表内大小统一采用 MiB（1 MiB＝1,048,576 字节）。参数由前后端共同使用，后端最终校验；超限或非法输入明确拒绝，不静默截断。

| 参数 | 首版基线 |
| --- | --- |
| 分页 | 页码从 1 开始；每页默认 20，允许 1～100；稳定排序 |
| 帖子标题与正文 | 标题 2～100 字符；正文 1～20,000 字符 |
| 评论、私聊 | 分别 1～2,000 字符；私聊只收文字 |
| 商品标题与描述 | 标题 2～100 字符；描述 1～5,000 字符 |
| 商品属性 | 类别、校区、成色从配置字典选择；首版校区选项为沙河、西土城、其他，其他须填地点；品牌或型号、用途各最多 100 字符，地点最多 100 字符 |
| 成色 | 全新、近新、良好、一般；未提供的可选属性不能推测为事实；缺失硬条件所需属性的商品不作为有效匹配 |
| 金额 | 人民币 0～99,999.99 元，最多两位小数；按整数分保存，筛选上下界均包含；支持免费商品 |
| 搜索和 AI 输入 | 搜索词 1～200 字符；自然语言需求 1～1,000 字符 |
| 图片类型 | JPEG、PNG、WebP；校验实际内容并解码；首版不接收 SVG、GIF |
| 头像 | 1 张，最多 2 MiB |
| 商品图片 | 必须 1～6 张，每张最多 5 MiB |
| 帖子图片与附件 | 图片最多 9 张，每张最多 5 MiB；另可附最多 2 个 PDF，每个最多 10 MiB |
| 用户文件配额 | 已成功保存且未清理的文件累计最多 200 MiB；未知类型、伪造类型、路径越界及配额不足拒绝，失败上传不占用有效配额 |
| 举报与公告 | 举报原因 1～1,000 字符；公告标题 2～100、正文 1～20,000 字符 |
| 监控任务 | 每人未删除任务最多 10 个，启用、暂停和异常均计入；周期为整数分钟，允许 5～1,440 分钟 |
| AI 解析 | 一次业务调用总超时 15 秒；不自动重复收费请求，失败转手动条件；每人每分钟最多 5 次解析，日常轮询不重复调用解析模型 |
| 调度 | 单轮超时 60 秒；租约 120 秒；并发最多 2；失败额外重试 3 次，等待 1、5、15 分钟 |
| 时间 | 数据统一按 UTC 保存，界面按 Asia/Shanghai 展示；接口使用含时区的明确格式 |

前端不得只用颜色表达已售、暂停、失败或已读等状态。Markdown 禁止原始 HTML 和可执行脚本，链接和文件访问使用同一权限规则。

## 六 容量与性能验收目标

验收数据固定为 50 个账户、1,000 条帖子、3,000 条评论、500 件商品、2,000 条消息及 100 个监控任务，均为模拟或授权数据。至少覆盖 2 个板块、两个不同浏览器的用户会话，以及版主和管理员角色。负载目标为 20 个并发普通 HTTP 请求和 10 条在线私聊连接，后台监控同时运行。

连续测量至少 5 分钟并记录环境、样本数和错误率：普通列表、详情、发布和评论接口 P95 不超过 1 秒，关键词搜索 P95 不超过 2 秒，语义检索 P95 不超过 3 秒；以上不含外部 AI 解析、文件上传和网络传输大文件的时间。已连接双方从发送到收到消息 P95 不超过 2 秒；AI 解析最迟 15 秒内返回结果或明确降级。

新增和编辑内容的语义索引更新目标为 60 秒内；隐藏、删除和权限变化必须在结果返回前即时过滤，不等待索引刷新。正常运行时，从商品保存到持久提醒的 P95 不超过所设监控周期加 120 秒；故障重试单独记录，不混入正常延迟统计。测试允许失败，但不得丢失已确认的持久写入、重复确认消息或越权；若目标未达到，必须修复或形成明确的需求变更记录，不能直接标为通过。

已知服务器为 4 核、16 GB，IP 为 `85.121.122.124`；该信息不是性能验证结果。T03 仅完成开发电脑的准备，服务器系统、磁盘、带宽和部署环境在 4.12 部署阶段核验。

## 七 验收用例

下表保留T01制定时的验收标准；当前实际执行状态见 [4.6后的验收范围表](../docs/acceptance/验收范围.md)。T01完成只表示标准确定，不能据此认定全部功能或性能已经通过。

| 编号 | 检查动作 | 必须观察到的结果 |
| --- | --- | --- |
| AC01 | 注册大小写不同但归一后相同账号；输入非法账号或边界密码 | 唯一性和长度规则有效；无明文密码；不能注册管理角色 |
| AC02 | 登录、登出后复用旧凭据；改密或封禁后复用其他会话 | 相应会话失效；实时连接 5 秒内关闭；失败登录达到阈值后限流 |
| AC03 | 管理员辅助重置密码；用临时凭据直接访问业务或过期后改密 | 仅允许有效期内强制改密；重置有审计，旧会话不可用 |
| AC04 | 两个板块发帖、回复、点赞收藏，重复点击并刷新 | 内容持久化；父评论关系正确；点赞收藏无重复关联 |
| AC05 | 修改他人帖子；版主管理未授权板块；通过改正文绕过隐藏 | 全部拒绝；授权板块可治理；关键操作有原因和审计 |
| AC06 | 按关键词、同义自然语言、类型及价格搜索；翻页 | 可检索帖子和商品；保留条件及稳定顺序；有类型与详情入口 |
| AC07 | 隐藏或删除已建向量索引的内容；用搜索、旧详情及文件直链访问 | 不暴露受限正文或附件；私聊、任务和私人通知不进入公共搜索 |
| AC08 | 发布商品，测试金额边界、免费、超精度和非法状态跳转 | 合法价格精确保存；非法金额拒绝；状态按第四节流转 |
| AC09 | 上传数量或大小超限、伪造类型、未知类型、非法路径及超配额文件 | 明确拒绝；无可访问残片；归属和配额正确 |
| AC10 | 两账户实时聊天、重复发送标识、接收者离线、断线后重连 | 先保存再确认；每条仅存一次；历史及未读可补读 |
| AC11 | 第三账户读取会话；管理员直接读取未举报私聊或个人条件 | 拒绝；管理员仅能看到职责允许的脱敏运行信息 |
| AC12 | 输入商品需求，修改预算及校区，模拟缺字段、乱格式和 AI 超时 | 条件可改；硬约束违规数为 0；解释来自商品事实；15 秒内降级 |
| AC13 | 创建监控、发布或编辑在售商品、重复执行，再修改任务条件 | 正确匹配；同任务同商品只提醒一次；日常轮询不重复解析需求 |
| AC14 | 商品预留、已售、下架或隐藏；任务暂停、删除或账户封禁 | 不提交新的无效提醒；历史通知显示当前状态 |
| AC15 | 模拟执行超时、领取后崩溃、数据库失败、Redis 清空及服务重启 | 租约回收、有限重试、异常状态和恢复有效；无重复通知，不丢已确认数据 |
| AC16 | 普通用户或版主调用封禁、授权、公告、任务管理；移除最后管理员 | 越权拒绝；最后可用管理员保留；合法管理操作可追溯 |
| AC17 | 提交帖子、商品及骚扰消息举报并处理；创建草稿和发布公告 | 用户只看自己的举报结果；消息仅按举报必要范围展示；草稿不公开 |
| AC18 | 在数据库或模型不可用、写入失败时操作并刷新 | 不显示虚假成功；普通搜索或手动条件可降级；恢复后数据一致 |
| AC19 | 按第六节数据、负载和时长执行性能测试 | 记录 P95、错误率、索引同步及通知延迟，逐项判断是否达标 |
| AC20 | 完成注册、发帖搜索、商品发布、AI 匹配、保存监控、新商品提醒和卖家私聊 | 全流程联通；重启后数据仍在；备份能在独立测试环境恢复 |

## 八 AI 对比评测

固定 500 件商品、40 条人工标注需求，其中至少 20 条包含同义表达或用途描述；用两名成员标注并讨论分歧，在比较前冻结查询、相关性标注及数据版本。报告关键词与语义方案的 Precision@5、Recall@5、NDCG@10，属性提取准确率及硬约束违规数。属性按字段比较，准确率目标不低于 90%，硬约束违规数必须为 0；整体 NDCG@10 不低于关键词基线，同义表达子集的 Recall@5 高于关键词基线。无已知相关结果的查询单列，不把它们纳入无定义的 Recall 计算。

另设置至少 20 次应提醒场景、20 次不应提醒场景及重复执行场景。报告提醒精确率、漏报和延迟；精确率目标不低于 90%，至少有一次有效提醒，重复通知数为 0，已售、下架及暂停删除场景无新增无效通知。评测目标尚未验证，不展示虚构的匹配百分比。
